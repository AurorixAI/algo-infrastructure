## Реальный банк: очередь проверки, не массовая обрезка

37 264 записи, 34 267 активны. Каноническая колонка — заполненный question_latex,
иначе question_text. Варианты считаются по отображаемым индексам answer_options,
с заполненным answer_options_latex того же индекса. Длины включают команды TeX:
они являются фильтром кандидатов, не числом видимых букв и не вердиктом ошибки.

- Условие >250: 1 414; >500: 92; >1000: 5; максимум 1 399 символов.
- Заданий с вариантом >120: 194; >250: 55; максимум варианта 1 754.
  Общая очередь: 147 ID; 12 имеют вариант >250 и как минимум четырёхкратное
  отношение к самому короткому непустому варианту — только флаг для review.
- Подробные численные итоги и полный обезличенный реестр ID находятся в
  [результате read-only SQL](p09-content-length-audit-2026-10-04.json).
- [SQL аудита](p09-content-length-audit.sql) воспроизводим; не меняет таблицы,
  не выбирает источник по длине и не раскрывает ответы учеников.

Проверены наиболее длинные записи и пять конкретных детальных записей. Причины:

- **L01 — несколько вопросов в одной записи:** `G5_TB_68_1675` (1 399),
  `G5_TB_68_1672` (912). Рассмотреть разделение на самостоятельные задания с
  необходимым общим контекстом; затем заново проверить ключ, skill mapping и IRT.
- **L02 — учебный текст без отдельного действия ученика:**
  `G11_TB_1_1_1_1` (1 265), `G11_TB_§2_2` (997).
  Проверить первоисточник и тип материала; сформулировать проверяемый вопрос
  либо исключить теоретический материал из диагностической выдачи с причиной.
- **L03 — решение уже в условии:** `G11_TB_8_4_6` (774).
  В тексте «Решим уравнение» уже приведены преобразования и окончательный ответ.
  Требуется содержательная проверка импорта/назначения; не исправлять просто CSS.
- **L04 — развёрнутое решение в вариантах:** `G11_TB_5_3_6_3` (до 1 754),
  `G11_TB_5_3_6_4` (до 1 264), `G11_TB_§11_1_3` (до 544).
  Особенно у первого задания правильный вариант много длиннее остальных:
  возможно угадывание по длине. У второго длинные варианты содержат разные знаки
  производной/экстремумы — их смысл нельзя терять при сокращении.
  Подготовить однозначный формат проверки; решение хранить отдельно от
  компактного, сопоставимого по форме ответа. Изменение проверяемого навыка
  требует явного нового mapping, а не скрытой подмены задачи.
- **L05 — длинный, но содержательный контекст/таблица:** `G5_TB_69_1681` (1 195),
  `G9_TB_6_72` (1 154), `G5_TB_58_1380` (1 068).
  Сохранить необходимые численные данные; структурировать текст/таблицу.
  Размер TeX-исходника таблицы не считается дефектом автоматически.

Все L01–L05 входят в N01 после защиты исторических попыток (R03). Для каждого
кандидата сохраняются исходник, причина решения и ключ/варианты. В этой работе
условия, ключи, mapping, параметры и is_active банка не менялись. Намеренные
деактивации рисунков сохранены. Содержательная очередь остаётся открытой.

## Второй скриншот: подтверждённый дефект общего CSS

У формул сочетались horizontal scroll с overflow-y:hidden и ручные переопределения
размеров script/fraction. KaTeX рассчитывает struts/offsets под собственные размеры;
ручное изменение размера текста нарушало согласование. Родитель скрывал верхние
и нижние части. Формула интеграла из T06 воспроизводит дефект.

Кандидат удаляет переопределения размеров script/fraction, оставляет нативную
геометрию KaTeX и резервирует вертикальный вынос glyphs внутри scroll box.
Горизонтальная прокрутка и канонический источник сохранены. Текст самой T06 и
неоднозначность метода приближённого интегрирования этим CSS не исправляются.

До/после: одинаковые synthetic HTTP fixtures на реальных страницах в Chrome,
ширины 360/768/1280. Интеграл, вложенные дроби/корни, скобка системы, широкая
формула. Шесть сценариев: диагностика, online экзамен, admin preview, teacher
draft, exam report и diagnostic error report. Всего 27 состояний.

Исходный HEAD: **38** зарегистрированных выходов glyph bounds за clipping box.
Кандидат: **0**, нет math parse errors, JS page errors и переполнения страницы.
[Baseline JSON](p09-before-math-layout-2026-10-04.json), [candidate JSON](p09-candidate-math-layout-2026-10-04.json).
В черновиках baseline не показал вертикального clipping для этих fixtures;
общий CSS проверен и там. Область утверждения ограничена этой матрицей.

Дополнительно исправлен перенос частей длинной display-формулы, который
накладывал строки дробей. Display сохраняет intrinsic width и прокручивается.

Production standalone build и сохранённая portable browser regression проверяют
также прокрутку широкой формулы до последнего края. Проверка включена в frontend
GitHub CI после build; fixture API не подменяет backend/RBAC acceptance.
Условие/ключи/parser/CAT не изменены.
