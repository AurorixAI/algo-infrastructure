# ALGO workspace

Этот workspace содержит независимые Git-репозитории, а не один монорепозиторий. Основной актуальный план: `algo-infrastructure/docs/engineering/ROADMAP.md`; принятые результаты и ограничения: `algo-infrastructure/docs/engineering/IMPLEMENTED_AND_LIMITS.md`.

Для изменения пользовательского сценария или бизнес-логики использовать проектный навык `algo-feature-delivery`: потребность → затронутые контракты → последствия → проверяемый результат. Для диагностики, банка и отчёта дополнительно использовать `algo-diagnostic-evidence`; для коммита, публикации и отката — `algo-git-release`. Канонические навыки находятся в `algo-infrastructure/.agents/skills/`; ссылки в workspace `.agents/skills/` подключают их без отдельных копий.

Обычные технические решения принимать в пределах запроса. Проверки выбирать по реальному риску изменения: содержательная регрессия для бизнес-логики, PostgreSQL/Redis для транзакций и гонок, браузер для UI, математическое решение и источник для ключей задач. Простой текст/CSS не требует полного backend-прогона.

Запланированный пункт, проверенный локальный кандидат, запушенный коммит и опубликованный image — разные статусы. Не объявлять аудит исправлением, синтетические прогоны эмпирической точностью, source-hash совпадение новой Git-сборкой.

Заполненный `question_latex` — источник условия; выбор по длине не возвращать. Решённые LaTeX-примеры и намеренные деактивации заданий с неподтверждёнными рисунками сохранять. Старые ответы и опубликованные задания не переписывать незаметно при изменении банка.

Каждый сервис коммитится отдельно. Использовать согласованную пользователем ветку; сейчас это `CEO`. `CEO` запускает проверки без автоматического deploy. Новый stage-релиз строить из точных pushed SHA и сохранять image/source/config bindings и rollback. Production находится в `algo-staging-*`, stage — в `algo-preview-*`: название staging не является разрешением на production.

Git/deploy и платные вызовы выполнять только в предоставленном пользователем объёме. Навык не расширяет разрешения. Секреты, дампы, приватные сессии и персональные доказательства не добавлять в Git.
