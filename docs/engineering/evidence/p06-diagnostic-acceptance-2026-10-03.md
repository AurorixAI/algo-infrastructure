# P06 — приёмка диагностики на stage

3 октября 2026, Asia/Tashkent. Проверены текущий банк, точные Linux образы, PostgreSQL/Redis и настоящий Chrome. Изменения опубликованы только на stage.algolab.me. Production сохраняет прежние контейнеры и конфигурацию. Данные банка, намеренные деактивации, рисунки и LaTeX не переписывались.

## Что изменено

1. Подбор заданий: content API ранжирует весь доступный пул навыка по расстоянию |b−theta| до LIMIT. Diagnostic передаёт target_b, включая ноль. Прежние вызовы без target_b сохраняют контракт. На живом stage проверены 20 навыков с большим смешанным пулом.
2. Новая ранняя остановка classification_confident: минимум 20 ответов, SE≤0,40, posterior mass текущей трёхуровневой IRT-категории ≥0,90, покрытие пяти разделов. Активная и ещё не начатая важная проверка пробела блокируют раннюю остановку. Предварительный просмотр навигатора не изменяет его состояние. Строгая ветка SE≤0,30 и hard cap42 сохранены.
3. Внутренний аудит хранит точную причину завершения, SE, model confidence и отдельные количества measurement/prerequisite вопросов. Вероятность считается с разделением ячеек posterior на границах −0,5 и 1,0. Fisher helper исправлен; он не используется активным подбором, поэтому сам по себе не ускоряет диагностику.
4. Итоговый отчёт: у попытки без ошибок низкая накопленная alpha больше не создаёт выдуманный пробел и коррекционный план. Заключение рекомендует развитие навыков. При реально ошибочных профилях рекомендации сохраняются. Версия производной структуры отчёта повышена до 3; worker, публичный и staff API используют одну версию. Ответы не переписываются. Только пять собственных QA-отчётов пересобраны для приёмки.
5. Карточка итогового отчёта: на узком экране оценка и подпись уровня размещены вертикально, подпись ограничена шириной карточки; дополнительные показатели появляются при достаточной ширине. Исправлено обрезание подписи, скрывавшееся за overflow-hidden.

По решению владельца пункт о новом показе неопределённости в интерфейсе исключён. Внутренние показатели используются алгоритмом и аудитом. Все 42 задания самостоятельной попытки поданы из question_latex.

Самостоятельная попытка решена по показанным условиям и вариантам без запроса ключей для этой попытки. Каждый расчёт записан в [журнале решений](../EVIDENCE_INDEX.md). Первый пример ранее попал в просмотренный отчёт профиля; его решение независимо проверено и это отмечено в журнале. В вопросе 17 верного вычисленного ответа среди вариантов нет: для продолжения через UI вынужденно выбран один вариант, который сервер засчитал. В вопросе 24 использовано явно записанное допущение о вписанном квадрате. Поэтому «42 засчитано» не означает, что все задания банка содержательно корректны.

Первые пять вопросов личной попытки распределены между функциями, уравнениями, показательной темой, тригонометрией/производной и вероятностью. После них шла навигация по навыкам, после 25 — precision_targeting. Задания не повторялись по ID. Повторные близкие задачи на преобразования графиков встречались под разными навыками; самостоятельная попытка включала несколько таких задач. При 42 правильных ответах SE осталась 0,4051>0,40, поэтому завершение по лимиту соответствует новому контракту.

PostgreSQL: 185 уникальных ответов, ровно по одной завершённой попытке и одному ready-отчёту на каждого из пяти QA-учеников, auth synced. Пересоздание производных отчётов сохранило хэш исходных ответов. Повтор последнего ответа и обновление страницы сохраняли тот же результат. После исправления у двух попыток без ошибок нет weak/critical blocks и коррекционного плана; у трёх ошибочных профилей планы сохранены.

## Проверки

- Финальный diagnostic образ: **193 passed**, без исключений/пропусков; isolated PostgreSQL/Redis, без оплачиваемых моделей.
- Content образ: **375 passed**, без пропусков; полная поддерживаемая suite. Служебные предупреждения о deprecated API не мешали прохождению.
- **742** offline прогона реального SessionService/IRT: 630 основных профилей в 5–11 классах, 42 крайних контроля и 70 пограничных прогонов. Ошибок нет. В основных профилях 410/630 остановились раньше: медианы длины 40/33/35 для сильного/среднего/пробелов. Эти ответы сгенерированы по текущим a/b/c и не являются наблюдениями реальных учеников. SQL-порядок равных сложностей отличается от фиксированного порядка offline-прогона.
- Точный frontend образ: 15 проверок пяти бизнес-статусов при 360/768/1280 px до публикации. После публикации реальные student/admin страницы проверены на этих же ширинах, включая границы подписи относительно карточки. Ошибок JavaScript/KaTeX и горизонтального выхода страницы нет.
- Все runtime-методы остановки/навигации финального diagnostic образа совпадают по AST с образом фактического browser passage; последующий report fix изменил только HTTP-флаг актуальности отчёта в SessionService. Алгоритм не расходится с пройденным сценарием.
- Проверены действующие образы, реальные env-параметры, Alembic heads, неизменность банка и production. Публичные stage version и production login доступны. В просмотренных хвостах логов текущих трёх обновлённых контейнеров нет ERROR, traceback и HTTP5xx; это проверка текущих контейнеров, а не архив логов удалённых предыдущих контейнеров.
- До обновлений сохранены приватные дампы diagnostic/content, прежние образы и compose-конфигурации для отката. QA-данные удалены только в двух помеченных организациях; проверены нулевые остатки. Production базы не использовались. Временный localhost frontend контейнер и приватные файлы приглашений удалены; после очистки stage работает.

## Содержательные находки

**G10_TB_3_9_9, личный вопрос 17.** Объявленная цена 12 000 000; производитель продаёт оптовику за 8 400 000 после скидки 30%; розница покупает за 9 600 000 после скидки 20% от объявленной цены. При ставке 10% добавленная стоимость даёт 120 000 для оптовика и 240 000 для розницы. Такого варианта нет. Сервер принял вариант 360 000 / 240 000. Нужна предметная проверка текста, вариантов и ключа по источнику. [Показанный экран](../EVIDENCE_INDEX.md).

**G10_TB_6_2_16, личный вопрос 24.** «Внутри круга нарисован квадрат» не задаёт площадь квадрата. Ответ 2/π требует вписанного квадрата и равномерного выбора точки. Рисунок не подан; общий ответ a²/(πR²). Требуется уточнение условия по источнику. [Показанный экран](../EVIDENCE_INDEX.md).

**G10_TB_§42_42_7_3, средний профиль.** В журнале задан вопрос о диапазоне (1;2), канонический вариант 1+1/(1+x²). При обычной вещественной области x=0 допустим и даёт 2; диапазон этой функции (1;2]. Другой вариант 2−1/(1+x²) даёт [1;2). Нужно проверить ограничения области определения и условие по источнику. Без дополнительного ограничения открытая верхняя граница не соблюдается.

**G10_TB_6_1_1, личный вопрос 35.** Текст представлен как готовое утверждение о несовместных событиях без явного вопроса. Среди вариантов есть корректная более сильная характеристика «противоположные». Ответ решаем по смыслу, но форму вопроса стоит проверить при содержательном аудите.

Эти находки зафиксированы без изменения банка, колонок отображения или активации рисунков. Они не требуют переоткрывать решённую задачу выбора LaTeX-колонки.

## Что остаётся

Эмпирическая точность и длительность на настоящих учениках ещё не подтверждены. a=1 у всех 32 887 связанных активных задач, b распределён по четырём стартовым значениям. Сильный/всегда-правильный ученик может всё ещё идти до42 при недостаточной информации о высоком уровне. Не следует обещать 20–25 каждому.

Classification confidence относится к трём внутренним IRT-категориям (границы −0,5 и 1,0). Существующий бизнес-отчёт использует пять статусов и процент засчитанных ответов; например, у сильного профиля IRT above_grade, бизнес-статус on_level при 78%. Эти правила сохранены, их согласование и проверка текущего накопительного alpha относятся к дальнейшей валидации модели/отчётов. Повышать a искусственно для сокращения теста не следует.

Следующие действия: предметная проверка найденных условий/ключей с сохранением question_latex; пилот с внешней оценкой учителя/независимого теста, затем калибровка a/b/c и проверка сложных задач. F2 остаётся частично выполненным из-за содержательной и эмпирической части. Техническая приёмка нового stopping/targeting на stage пройдена.
