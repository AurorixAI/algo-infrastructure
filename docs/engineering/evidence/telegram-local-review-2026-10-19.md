# Telegram Mini App — локальный обзор

Дата: 19.10.2026, Asia/Tashkent. Объём после уточнения владельца — локальная папка `telegramapp`. Это обзор существующего прототипа, не исправление и не приёмка опубликованного приложения.

## Вывод

Есть собранный интерфейс личного кабинета ученика. Его можно использовать как основу обсуждения продукта. Подключение настоящего ученика, данные ALGO и серверные действия в проверенной копии не реализованы. У папки нет `.git`, поэтому Git SHA и соответствие удалённой версии не установлены.

## Что уже есть

- React 18, Vite 5, Tailwind; Telegram SDK wrapper с `ready`, `expand`, closing confirmation и haptic feedback.
- Три основных раздела: «Главная», «Учёба», «Успехи». Внутри — расписание, посещаемость, результаты/детали экзамена, ALGO Coins. Профиль открывается отдельно.
- Экран согласия с локальным флагом, карточка ученика/группы, визуальная карточка пропуска, расписание, журнал посещений, история экзаменов и магазин наград.
- Python polling-бот и Netlify webhook, предлагающие открыть Mini App. Их живое состояние не проверялось.

## Подтверждённые ограничения

1. **Ошибки API скрываются демоданными.** `src/services/api.js:316–347` при любом отказе четырёх GET (включая 401/403, 404, 5xx и неправильный JSON) возвращает вымышленные профиль, расписание, посещаемость и результаты. Обозначения demo в интерфейсе нет. Локальный просмотр без API воспроизводит этот путь.
2. **Нет Telegram-авторизации и привязки ученика в проверенном backend.** Клиент передаёт `X-Telegram-Init-Data`; `/student/auth/identify` и `/student/auth/verify-contact` объявлены, но UI их не вызывает (`api.js:351–367`, `App.jsx:43–80`). Все шесть `/student/*` маршрутов отсутствуют в проверенных src/tests/migrations auth/exam/diagnostic и инфраструктурной конфигурации. Не найдены Telegram HMAC/TTL и связь Telegram ID с организацией/учеником. Это результат проверки локальных источников, не живого сервера.
3. **Подтверждения без выполнения.** Уведомление об отсутствии (`ScheduleScreen.jsx:94`) и запрос PDF (`AcademicResultsScreen.jsx:35`) меняют только состояние компонента. При этом UI утверждает «Уведомлен» / «Отчёт отправлен куратором в Telegram!». Покупки Coins также локальны.
4. **Разбор экзамена теряет данные.** API отдаёт `title`, `insight`, `user_answer`, `correct_answer`, а экран читает `topic`, `error_note` (`AcademicResultsScreen.jsx:146–152`). В браузере вместо объяснений показаны «Задание №3» и «Задание №5».
5. **Пустота и нулевой результат заменяются выдуманными значениями.** Главная подставляет занятие и результат 92% (`HomeScreen.jsx:17,46`), пустой список вопросов — пять заданий по квадратным уравнениям (`AcademicResultsScreen.jsx:45`), диагностический `0%` превращается в `86%` из-за `||` (`:222`).
6. **Coins и пропуск — демонстрация.** Баланс начинается с 350 и меняется только в компоненте, после ухода с вкладки сбрасывается; feature flag организации не проверяется (`GamificationScreen.jsx:11,120–146`). На пропуске — иконка QR, не кодируемый идентификатор доступа (`HomeScreen.jsx:161`).
7. **Токен бота записан в исходниках.** Литералы найдены в `bot_listener.py`, `verify_tma_status.py`, `netlify/functions/bot.js`; в webhook есть fallback на литерал при отсутствии env. Значение в отчёт не включено, работоспособность токена и утечка не устанавливались. Webhook не проверяет секрет входящего запроса. Перед использованием бота это требует отдельного исправления.

## Доступные данные основного продукта

Действующие staff API содержат исходные данные, но не заменяют ученический доступ:

- `auth-service/src/auth/router.py:569,589,977`: профиль, посещаемость, расписание; cookie/Bearer JWT и staff роли. Проверка организации/группы — `src/auth/service.py:866–911`.
- `exam-service/src/api/router.py:4724`: история только submitted экзаменов с проверкой видимости ученика и организации.
- `diagnostic-service/src/api/analytics_router.py:256`: аналитический отчёт с staff-доступом через auth-service.
